# C6 Career Operating Model

## SOP / SOMS

Audit -> Evidence -> Diagnose -> Recommend -> Select capabilities -> Execute -> Measure -> Re-audit -> Prove change.

A career mission is not complete because a CV was generated. It is complete when the promised work has been executed, measured and backed by evidence.

## Arsenal-first

Before adding a provider or writing a new subsystem: resolve the capability in the C6 Agent Arsenal; prefer an existing confirmed provider; check risk, permissions, runtime and production pin; use an adapter; execute least-privilege; verify; store evidence.

Career capability boundaries: workflow automation -> n8n/DIESEL CONNECT; scheduling -> Cal.com; knowledge/context -> Context-Hub/OpenViking; multi-agent work -> ClawTeam/Agency-Agents/CrewAI/MetaGPT; web research -> Scrapling/Page-Agent/HeadlessX; transactional email -> C6-Mail-Services. Supabase/PostHog/Plausible/Coolify require runtime and production-pin verification before activation.

Gmail and Notion are not core dependencies. The inherited upstream commands remain historical adapters and must not become the architecture source of truth.

## Win Architecture

Every meaningful career objective carries Target Win, Proof and Next Win. The Win Ledger is append-only. Lifecycle: WIN -> ABSORB -> VERIFY -> SCALE and CAPTURE -> PROVE -> REGISTER -> ESCALATE.

## Acceptance

Delivery evidence must identify capability, provider/adapter, execution result, measurement/evidence, and resulting win or blocked state.

## Data boundary

Public source code contains the engine and UI only. Personal identity, CVs, certificates, references, applications, mail signals and generated packs remain in private storage.
